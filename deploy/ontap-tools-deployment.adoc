= ONTAP tools をシングルノードアプライアンスとして導入する
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
NFS および VMFS データストアをサポートする超小型シングルノードアプライアンスとして、ONTAP tools for VMware vSphere を導入します。導入プロセスには最大 45 分かかります。

.作業を開始する前に
超小型のシングルノード構成を導入する場合、コンテンツライブラリはオプションです。マルチノード構成または HA 構成の場合、コンテンツライブラリが必要です。

VMware では、コンテンツライブラリに VM テンプレート、vApp テンプレート、およびその他のファイルが格納されます。コンテンツライブラリを使用すると、テンプレート操作中に直接的なネットワーク アクセスに依存しないため、展開が簡素化されます。

コンテンツライブラリを作成する前に：

* クラスター内のすべてのホストがアクセスできるように、共有データストアにコンテンツ ライブラリを作成します。
* ONTAP tools for VMware vSphere OVA をデプロイする前に、コンテンツライブラリを作成してください。
* デプロイ後もOVAテンプレートはコンテンツライブラリに保管してください。



NOTE: 後で HA を有効にする予定がある場合は、ONTAP tools の VM を ESXi ホスト上に直接配置するのではなく、ESXi クラスタまたはリソース プールに配置してください。

コンテンツライブラリを作成するには：

. ONTAP tools for VMware vSphere のバイナリ（_.ova_）と署名済み証明書を https://mysupport.netapp.com/site/products/all/details/otv10/downloads-tab["NetApp Support Site"^]からダウンロードします。
. vSphere Clientにログインします。
. vSphere Client メニューから、「コンテンツライブラリ」を選択します。
. 「作成」を選択します。
. 名前を入力して、コンテンツライブラリを作成してください。
. 作成したコンテンツライブラリを開きます。
. *Actions* > *Import item* を選択し、OVA ファイルをインポートします。



NOTE: 詳細については、 https://blogs.vmware.com/vsphere/2020/01/creating-and-using-content-library.html["コンテンツライブラリの作成と使用"]を参照してください。


NOTE: デプロイ前に、クラスタの分散リソース スケジューラ（DRS）を「保守的」に設定して、インストール中の VM 移行を防止してください。

ONTAP tools for VMware vSphere は、最初は非HA構成で展開されます。ONTAP tools 10.6 以降、CPU ホット アドおよびメモリのホットプラグはデフォルトで有効になっています。後でHA構成に拡張するには、これらの機能を有効にする必要があります。

.手順
. ONTAP tools の OVA ファイルと署名済み証明書を https://mysupport.netapp.com/site/products/all/details/otv10/downloads-tab["NetApp Support Site"^]からダウンロードします。既に OVA をコンテンツライブラリにインポートしている場合は、この手順をスキップしてください。
. vSphereサーバにログインします。
. OVA をデプロイするリソース プール、クラスター、またはホストに移動します。
+

IMPORTANT: ONTAP tools VM は、管理対象の vVols データストアに保存しないでください。

. OVAファイルは、コンテンツライブラリまたはローカルシステムから展開してください。
+
|===


| ローカルシステムカラ | コンテンツライブラリから 


| a.右クリックして*[Deploy OVF template...]*を選択します。b. URLからOVAファイルを選択するか場所を参照し、*[Next]*を選択します。 | A.コンテンツライブラリに移動し、導入するライブラリアイテムを選択します。B.* Actions *>* New VM from this template *を選択します。 
|===
. 「名前とフォルダを選択」に、VMの名前と場所を入力します。
. コンピュータリソースを選択し、* Next *を選択します。必要に応じて、[Automatically power on deployed VM]チェックボックスをオンにします。
. テンプレートの詳細を確認し、* Next *を選択します。
. ライセンス契約を読んで同意し、* Next *を選択します。
. 構成用のストレージとディスクフォーマットを選択し、*[次へ]*を選択します。
. 各ソースネットワークのデスティネーションネットワークを選択し、*[Next]*を選択します。
. *テンプレートのカスタマイズ*ウィンドウで、必要な値を入力します。image:../media/custom-temp-p2.png["Customize template"]
+
[IMPORTANT]
====
「テンプレートのカスタマイズ」ページの値は、正常にデプロイするために必須です。

特に以下のフィールドに注意してください：

** *ホスト名*：ONTAP tools VM のホスト名を入力してください。有効なホスト名形式を使用してください。
** *ONTAP tools の IP アドレス*：これは、ONTAP tools へのアクセスに使用するプライマリ管理インターフェイスです。
** *IPv4アドレス*：これは、トラブルシューティングとメンテナンスのための診断シェルとSSHアクセスに使用されるノードのIPアドレスです。


ホストまたはvCenterに DNS 名を使用する場合は、それらの名前が DNS で正しく解決されることを確認してください。

====
+

NOTE: vCenter ホスト名は、 ONTAPツール アプライアンスがデプロイされている vCenter Server インスタンスの名前です。

+
2つのvCenter Serverトポロジ（アプライアンスが1つのvCenterインスタンスにホストされ、別のインスタンスを管理する構成）にONTAP toolsをデプロイする場合は、ONTAP toolsをホストするvCenterインスタンスに制限付きロールを割り当ててください。OVFテンプレートのデプロイに必要な権限のみを持つ専用のvCenterユーザーとロールを作成してください。詳細については、link:../concepts/rbac-vcenter-use.html#vsphere-object-hierarchy["ONTAP Tools for VMware vSphere 10に含まれるロール"]を参照してください。

+
ONTAP tools で管理される vCenter インスタンスについては、vCenter ユーザーアカウントに管理者権限があることを確認してください。

+
** ホスト名には、文字（A-Z、a-z）、数字（0-9）、ハイフン（-）を含める必要があります。デュアル スタックの場合は、IPv6 アドレスにマッピングされたホスト名を指定してください。
+

NOTE: 純粋なIPv6はサポートされていません。IPv6アドレスとIPv4アドレスの両方を含むVLANでは、混合モードがサポートされます。

** ONTAP tools の IP アドレス（旧ロードバランサー）は、ONTAP tools Manager (`\https://<ip>:8443/virtualization/ui/`）、API 呼び出し、および vCenter UI からのプラグイン アクセスの外部エンドポイントです。
** ONTAP tools の仮想 IP アドレス（旧称ノードインターコネクト）は、Kubernetes API （kube-api）サーバーに割り当てられ、Kubernetes コントロールプレーンの仮想 IP として機能します。
** IPv4アドレスは、指定されたホスト名にマッピングされたノード管理アドレスであり、診断シェルおよびSSH アクセスに使用されます。


. [選択内容の確認]ウィンドウで詳細を確認し、*[終了]*を選択します。
+
デプロイタスクが開始されると、進行状況がvSphereタスクバーに表示されます。

. 自動電源オンを選択しなかった場合は、タスク完了後に仮想マシンの電源をオンにしてください。


VMのWebコンソールからインストールの進行状況を追跡できます。

OVFフォームに不一致がある場合は、修正措置を促すダイアログボックスが表示されます。タブキーを使って移動し、必要な変更を行い、*OK* を選択してください。問題解決のための試行回数は3回です。3回試行しても問題が解決しない場合は、インストールが停止しますので、新しい仮想マシンでインストールを再試行してください。
